Setting Up an AI Sandbox for Ollama With Lima

2026.11.123 min read

In order to let a coding agent loose on your computer, it is recommended to run models in a sandbox.

This is because, even if you give strict permissions to models, they can still find ways around that, and there have been cases where people have deleted their whole hard disk or similar, because agents did something stupid by mistake.

There are various ways of running sandbox, and after some research, I have came to the conclusion that for me, running Linux Mint on my development machine, a sandbox running in a virtual machine is a good compromise between safety and ease of use.

I have fond memories of using Vagrant in the past, where one could easily configure and get up a virtual machine from a code based repository.

HashiCorp, the company behind Vagrant, has changed the license terms recently though and so Vagrant doesn’t seem to be maintained as well in the future, and is also quite clunky as depending on VirtualBox.

Turns out there is a new solution out there called Lima , which is based on the Qemu virtualization technology, which is ligher than VirtualBox. It is also a Cloud Native Computing Foundation incubation project, which is promising for future maintenance.

In this guide I will succinctly document how I set up a Lima-based sandbox on my computer, for running Ollama (I’ve got a subscription there) cloud based open weight models like DeepSeek 4.1 Flash on my computer.

Prerequisites

These steps were run on Linux Mint 21.1 Vera, but should be largely similar on most recent Ubuntu-based distros.

Install some dependencies

Run this in a terminal:

sudo apt update -y
sudo apt install -y \
    qemu-system-x86 \https://lima-vm.io/
    qemu-utils \
    uidmap \
    socat \
    jq \
    curl \
    git

Pull down an image

Inside a folder created for the purpose, run this in a terminal:

curl -fL \
    https://cloud-images.ubuntu.com/noble/current/noble-server-cloudimg-amd64.img \
    -o noble-server-cloudimg-amd64.img

Add this to a file, opencode-ollama-sandbox.yaml

# Ubuntu 24.04 sandbox
vmType: "qemu"
arch: "x86_64"

images:
  - location: "./noble-server-cloudimg-amd64.img"
    arch: "x86_64"

cpus: 2
memory: "4GiB"
disk: "40GiB"

# Only expose the dedicated workspace.
mounts:
  - location: "~/wrk"
    mountPoint: "/wrk"
    writable: true

provision:
  - mode: system
    script: |
      #!/bin/bash
      set -eux

      apt-get update
      apt-get install -y \
        ca-certificates \
        curl \
        git \
        build-essential \
        jq \
        unzip \
        python3 \
        python3-venv

      # Install Ollama.
      curl -fsSL https://ollama.com/install.sh | sh

Create the VM

limactl create --name <vmname> opencode-ollama-sandbox.yaml

Start OpenCode via Ollama inside the Lima container

limactl shell <vmname> -- ollama launch opencode

This is of course great to put in an alias in ~/.bash_aliases, e.g:

alias looc='limactl shell olcode -- ollama launch opencode

You can also always just use the interactive Lima shell tool to navigate into the options. To do this, just run:

limactl

… and you will be presented with your currently set up images that you can then enter, with a shell, or other actions.

Try it out!
